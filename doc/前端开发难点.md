# 前端开发难点：顶部导航吸顶与 tab 切换状态保留

## 1. 需求目标

本次交互的核心目标不是让整个 header 吸顶，而是让 tab 导航在滚动到顶部附近之后保持吸顶；同时在切换 tab 时，如果当前已经处于吸顶状态，不应因为新 tab 内容更短而被“弹回”正常流动状态。

业务要求可以概括为：

- Header 不固定，不参与滚动吸顶
- 子页面滚动时，nav 作为独立模块吸顶
- nav 吸顶后切换到更短内容的 tab 时，仍然保持吸顶
- 只有当用户再次回到顶部附近，或者达到明确的“释放条件”时，才恢复非吸顶状态
- 不要在 tab 切换时因页面重置导致状态丢失

---

## 2. 难点一：CSS sticky 和固定定位的边界

最开始很容易犯的错误是把整个 header 也做成 fixed/sticky，导致视觉上“高层级的元素一起飘起来”，不符合设计要求。

正确思路：

- header 保持 `position: relative`
- nav 单独维护自己的 sticky/fixed 状态
- 让 nav 只在需要时转为 fixed，且固定在页面顶部

示例思路：

```css
.header {
  position: relative;
}

.tab-navigation {
  position: sticky;
  top: 0;
  z-index: 20;
}

.tab-navigation.pinned {
  position: fixed;
  top: 0;
  left: 50%;
  transform: translateX(-50%);
  z-index: 30;
}
```

注意：

- `position: sticky` 适合“自然流布局中持续参与滚动”，但不适合强要求“切页后保留锁定状态”的复杂 UX
- 真正要做的是状态驱动的固定，不只是 CSS 自身行为

---

## 3. 难点二：tab 切换会触发页面状态重置

这是这次最关键的工程问题。

在 Vue 里，切换 tab 常常伴随：

- 页面内容切换
- 组件重新渲染
- 滚动位置重置
- 视口高度变化
- sticky 状态重新计算

如果逻辑只用 `scrollY <= threshold ? false : true` 这种简单判断，就会导致：

- 用户已经吸顶
- 切换到更短内容的 tab
- 新 tab 内容高度不足，页面重新布局
- `window.scrollY` 变小/变为 0
- 吸顶状态被判定为“未吸顶”，直接解除

这就是“切 tab 之后 nav 立刻掉下来”的根因。

---

## 4. 正确方案：增加“锁定状态”而不是只看瞬时 scrollY

要解决这个问题，不能只依赖 `window.scrollY` 做一次性判定，而要把状态分成两层：

1. 是否已经进入吸顶状态
2. 是否允许在当前时刻解除吸顶

推荐状态字段：

```ts
const tabNavPinned = ref(false)
const tabNavReleaseGuardUntil = ref(0)
```

关键策略：

- 只要 nav 已经是 pinned，切换 tab 时先保留它
- 只有当用户滚回到顶部附近，且通过 guard 条件通过时，才解除
- 例如：
  - 允许在 `scrollY <= 12` 时判断是否释放
  - 但如果刚切换 tab，给一个短暂保护窗口（比如 500ms）

伪代码：

```ts
function updateTabNavSticky() {
  const scrollY = window.scrollY
  const now = Date.now()

  if (scrollY <= 12 && now > tabNavReleaseGuardUntil.value) {
    tabNavPinned.value = false
    return
  }

  if (scrollY > 12 || tabNavPinned.value) {
    tabNavPinned.value = true
  }
}

watch(activeTab, () => {
  if (tabNavPinned.value || window.scrollY > 12) {
    tabNavPinned.value = true
    tabNavReleaseGuardUntil.value = Date.now() + 500
  }
})
```

这类逻辑的目标是：

- 让 sticky 具备“锁定感”
- 让用户觉得 nav 是“被固定住了”，不是临时 CSS 触发
- 避免在切页时被违反设计意图地“抬起”

---

## 5. UX 设计要求：只有 nav 吸顶，不要固定 header

这是产品体验层面的根本要求。很多前端问题的关键其实不在 JS，而在“需求理解”层面：

- header 是页面结构，不应该跟着滚动固定
- nav 是导航器，应该在子页面滚动时凭借同一入口实现吸顶

因此页面结构上推荐：

- header 作为普通布局元素，不绑定 sticky/fixed
- nav 作为独立元素，单独控制吸顶状态
- nav 吸顶时给出明确视觉反馈，比如：
  - 更强的阴影
  - 背景半透明/毛玻璃
  - border-bottom
  - 更高层级 z-index

这样用户会更清楚：

> 这是导航被吸住了，不是页面整体被固定住了。

---

## 6. 视觉设计建议：做成“有设计感的 tab 导航”

本次实现中，tab 的视觉效果要体现“高级后台管理系统”的质感，而不是单纯的按钮组。

建议使用以下视觉层级：

- 玻璃态背景：背景色轻透、边框淡白、适度高斯模糊
- active tab 使用高对比度色块或涂层
- tab 之间保留合理间距，不挤在一起
- 选中项用滑块/背景色块突出，营造现代 tab 体验
- pinned 状态时额外增加阴影，让固定感更明显

这类导航的核心不是“功能可点”，而是“人在滚动过程中，自然感觉它一直在顶端”——这需要视觉状态和交互状态保持一致。

---

## 7. 一次真实坑：Vite 的代理配置会把前端资源误打到后端

这类前端问题不只是页面样式，还会影响运行状态。

在开发时，配置代理时要注意：

- 不能简单用 `/node` 这类宽泛规则覆盖前端依赖路径
- 例如 `node_modules` 或 Vite 内部模块请求，可能被错误转发到后端
- 这样会出现 500/资源加载失败，表现为页面看起来“前端坏掉了”，但实际上是路由被错误代理

正确原则：

- 仅代理真实业务接口，如 `/api`, `/sub`, `/node/`, `/dl`
- 不要让 Vite 的静态资源 路径 与后端 API 路径混淆

这类问题在开发中很容易被忽略，因为它不是业务逻辑错误，而是网络层错误。

---

## 8. 最终方案：自然吸顶 + 锁定状态 + 平滑过渡

这次真正落地的方案，核心不是“山寨的固定定位”，而是用状态机 + 自然布局过渡处理吸顶行为。

### 8.1 关键思路

1. `sticky` 仍然保留：nav 用 `position: sticky`，保持自然流体行为
2. 只有当 nav 自身顶部接触到视口顶部时，才认为它进入吸顶状态
3. 一旦进入吸顶，就锁定状态，避免切换到更短内容的 tab 时因布局变化把 nav 重新压回正常流动状态
4. 只有在用户真实做“向上回顶”的滚动动作时，才解除锁定
5. 视觉层面增加柔和过渡，让从普通状态到吸顶状态不再突兀

核心思想可以概括成：

- 进入条件：`navTop <= 1`
- 锁定条件：一旦已吸顶，就保留 `tabNavPinned` / `tabNavLock`
- 释放条件：只有在真实向上回顶时才解除

这一层逻辑的关键点是：

- 不用只看 `scrollY` 是否大于某个阈值
- 不用让 `scrollY` 归 0 自动当作“自然结束吸顶”
- 需要把“当前是否已经吸顶”与“是否允许释放”区分开

---

## 9. 核心代码：状态锁定与自然触发

下面这段逻辑是最终方案的核心：

```ts
const tabNavPinned = ref(false)
const tabNavLock = ref(false)
const tabNavReleaseGuardUntil = ref(0)
let lastScrollY = 0

function updateTabNavSticky() {
  const navEl = document.querySelector('.tab-navigation') as HTMLElement | null
  if (!navEl) return

  const navTop = navEl.getBoundingClientRect().top
  const currentScrollY = window.scrollY
  const now = Date.now()

  if (now < tabNavReleaseGuardUntil.value) {
    tabNavPinned.value = true
    return
  }

  if (tabNavLock.value) {
    if (currentScrollY <= 12 && lastScrollY > 0 && currentScrollY < lastScrollY) {
      tabNavLock.value = false
      tabNavPinned.value = false
      lastScrollY = currentScrollY
      return
    }

    tabNavPinned.value = true
    lastScrollY = currentScrollY
    return
  }

  if (navTop <= 1) {
    tabNavPinned.value = true
    tabNavLock.value = true
  } else {
    tabNavPinned.value = false
  }

  lastScrollY = currentScrollY
}

const handleTabNavScroll = () => updateTabNavSticky()

watch(activeTab, () => {
  const navEl = document.querySelector('.tab-navigation') as HTMLElement | null
  if (!navEl) return

  if (tabNavPinned.value || navEl.getBoundingClientRect().top <= 1) {
    tabNavPinned.value = true
    tabNavLock.value = true
    tabNavReleaseGuardUntil.value = Date.now() + 300
    return
  }

  tabNavReleaseGuardUntil.value = 0
  tabNavLock.value = false
  updateTabNavSticky()
})
```

这段代码的重点：

- `navTop <= 1` 是自然吸顶判定
- `tabNavLock` 是锁定态
- `tabNavReleaseGuardUntil` 是切 tab 后短时间保护窗口
- `lastScrollY` 用来判断是否真的发生了“回到顶部”的向上滚动

也就是说：

- 不是把 `scrollY` 当成唯一依据
- 而是把“已吸顶”和“允许解除”两个状态拆开

---

## 10. 视觉平滑过渡：不要让 nav 在顶部附近猛地硬切

如果只靠 CSS sticky，用户视觉上会有明显硬切感。为了让过渡更自然，建议把 pinned 状态设计成增强型视觉，不直接硬改成 fixed。

核心 CSS：

```css
.tab-navigation {
  position: sticky;
  top: 0;
  z-index: 110;
  display: flex;
  align-items: center;
  gap: 6px;
  margin: 18px 0 20px;
  padding: 8px;
  border: 1px solid rgba(148, 163, 184, 0.2);
  border-radius: 18px;
  background: rgba(15, 23, 42, 0.68);
  backdrop-filter: blur(18px);
  box-shadow: 0 10px 30px rgba(15, 23, 42, 0.25);
  overflow: hidden;
  isolation: isolate;
  transition:
    box-shadow 0.22s ease,
    border-color 0.22s ease,
    background 0.22s ease,
    transform 0.22s ease;
}

.tab-navigation.pinned {
  box-shadow: 0 16px 32px rgba(15, 23, 42, 0.35);
  border-color: rgba(148, 163, 184, 0.35);
  background: rgba(15, 23, 42, 0.82);
  transform: translateY(-2px);
}
```

这样做的收益：

- 用户感觉它是在“自然靠近顶端后变得更稳”
- 不会出现刚好到阈值时“啪地一下跳到顶端”的突兀感
- 即使切换 tab，视觉仍然保持连续性

---

## 11. 一次关键踩坑：不要对“滚动归 0”做误判

这次最容易踩的坑，是把下面这个判断当成通用逻辑：

```ts
if (window.scrollY <= 12) {
  tabNavPinned.value = false
}
```

这在很多情况下都不成立，因为：

- 切换 tab 时，页面可能被强制重置到顶部
- 内容高度不同，页面布局变化后 `scrollY` 会变成 0
- 这样就会把“已经吸顶”的状态误判为“恢复正常状态”

真正正确的方法是：

- 把吸顶状态看成持久状态
- 只有在“用户确实向上滚动回到顶部附近”时才解除
- 切换 tab 不应直接清空状态

---

## 12. 设计要求的最终落地

最终效果符合以下几条：

1. Header 不固定
2. nav 自然在到达顶部时吸顶
3. 从高内容 tab 切到低内容 tab 时，nav 继续保持吸顶状态
4. 只有真实回顶时，才解除吸顶
5. 视觉上通过过渡动画平滑衔接，不突兀

---

## 13. 结论

这次问题的核心不在 CSS sticky 本身，而在状态管理：

- 需要把“吸顶判定”与“吸顶释放”拆开
- 要让 nav 在进入吸顶后保持锁定
- 再通过视觉过渡让它像自然动作，而不是硬切

因此，最终实现方案是：

- 自然触发：`navTop <= 1`
- 锁定保留：切 tab 时保留 `pinned` 状态
- 平滑衔接：增加过渡和增强视觉层级

这就是这次前端交互最关键的工程思路。
